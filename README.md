## 介绍

通过 CUDA 手写实现 BF16 Dense GEMM（C = A × Bᵀ），从零独立完成核函数
设计与实现。受平台评测环境限制，优化决策基于 A800 硬件参数的静态分析调优。

## 核心设计

### 三层分块矩阵

1.**Warp 级（寄存器 / Tensor Core）**：每 warp 承担 8×4 个
   `m16n8k16` fragment tile，数据从 smem 一次性载入寄存器后在
   整个 K 循环内驻留，直接喂给 MMA，不再回 smem。  
2. **Block 级（L2 → shared memory）**：按 `BM × BN` 分块、`BK` 步进，
   将 A 的 `BM × BK` 与 B 的 `BK × BN` 子块搬入 smem，
   同一份数据被 block 内所有 warp 复用。  
3. **CTA 级（显存 → L2）**：在L2 cache层面，将每个tile视为基础元素，再做一层分块矩阵，
   在每轮矩阵运算中，沿较大输出维度分组遍历，使较小维度的操作数 tile 组在 L2 中驻留复用，提升L2层的命中。  

### 累加器方案
- 在SM的寄存器文件中分配专用空间作为累加器，用于暂存中间计算结果，累加寄存器按线程均匀划分，每个线程持有一份累加器阵列。
- 在 K 维度的迭代计算过程中，数据始终驻留在寄存器内并进行原位累加，避免频繁的中间状态写回。
- 直至 K 维计算完全结束后，再将最终的累加结果统一写回显存。

### 数据搬运路径优化

1. **显存 → smem**：用 16B 对齐的 `cp.async` 异步搬运，绕过寄存器文件和 L1，
   矩阵计算和数据搬运异步进行，且释放更多寄存器资源给累加器。
2. **smem → 寄存器**：通过 `ldmatrix` 以warp协同一次批量加载整个 fragment，
   替代每线程独立的 4B smem 读取，避免地址分散产生额外 smem 事务。
3. **smem 布局**：在 tile 行距上增加 padding，使同一 warp 各线程的
   访问地址错开不同 bank，降低访问冲突。

### 两级双缓冲流水线

1. **smem 层**：`cp.async.cg` 双缓冲，让当前 tile 计算与下一 tile 预取重叠。
2. **寄存器层**：对 fragment 二级双缓冲，`ldmatrix` 与 `mma` 交错发射，尽量保证 Tensor Core 不空转。

### 启发式参数计算
- **模板参数化**：BM、BN、BK用作模板参数，在调用时声明尺寸，
   根据M、N、K的不同，设计更合理的tile尺寸，提升计算效率。
- **L2 感知调度**：依据 L2 容量约束和 DRAM 流量模型，枚举分组方向（沿 M 或沿 N）与 group size大小，
   选取全局访存量最小的组合。

### 其他要点
- **转置处理**：B 按 `[N, K]` 原始布局整行搬入 smem，逻辑等效 col-major Bᵀ，
  复用 MMA 的 row-col 布局，免去 `ldmatrix.trans` 和显式转置。
- **边界处理**：完整 tile 走无分支快路径；边缘 tile 零填充使 MMA 计算
  完全不感知边界；写回阶段按线程常量判断走 `bf162` 向量化或逐元素路径。
- **精度**：FP32 累加 + 累加器原地截断写回为 bf16，避免计算误差的同时降低显存带宽压力。
